# 自主拟人社交

## 它解决什么问题

让 bot 在**没有收到消息的时候**也主动找熟人说话，而且说得像个有自己生活的人，不像一个定时器。

主动开口其实是几件不同的事，本插件把它们走成几条互不依赖的路：

| | 什么时候开口 | 靠什么 |
|---|---|---|
| **早晚问候** | 到点就说：早安/晚安窗口 | `greeting_*`（不看念头，每人每天每窗口一次） |
| **另起一个新话题** | 慢慢来：得真的想说（念头攒满） | `urge_refill_hours`、`activity_level`、作息画像 |
| **追问那件事** | 几分钟：对方回得越来越敷衍 | `probe_after_minutes`（不看念头） |
| **问一句在不在** | 十几分钟：话说到一半人没了 | `followup_after_minutes`（不看念头） |
| **回访没结果的事** | 几小时到一夜：你提过一句没说后来 | `loop_min_hours` / `loop_max_hours` |
| **给悬着的话收场** | 几小时到几天：她主动发的没人接 | `closer_after_hours`（最多收三次） |

> 每个用户**独立计算**：A 被找过不会让 B 多等。每个人自己的念头与
> `user_cooldown_minutes` 才是节奏来源；`max_sends_per_round` 只是别在一轮心跳里
> 把话一口气全倒出去的护栏。

## 群聊心流

上面那些都是**私聊**主动。群聊侧三条路由 `group_*` 开关控制，与 `private_only` 互不影响：

| | 什么时候 | 靠什么 |
|---|---|---|
| **心流接话** | bot 在群里说过话后的关注窗口内，群里继续聊 | `group_flow_enabled`、`flow_window_minutes`（无 @，模型可拒答） |
| **冷场破冰** | 群安静超过几小时 | `group_icebreak_enabled`、`group_idle_hours` |
| **发言参考库** | 生成时注入「这个群怎么说话」 | `group_ref_lib_enabled`、`group_ref_prompt_count` |

> **保守档**：心流只在 bot 自己刚发过言后的窗口内才可能无 @ 接话，不主动盯整个群。
> **不刷屏**：两次插话最短间隔、每窗口上限、每群每小时总上限、连着没人接就安静，四道闸叠着拦。
> **安静时段对群聊同样生效**：深夜群里有动静她也不会插话（这一点曾经漏掉过，已修）。
> **被踢就不再管**：心流只由实时群消息驱动；群发送失败隔离 24h；超 `group_stale_days`
> 天没见消息的群连样本一起清。用「群社交状态」指令（仅主人）看在管的群。
>
> ⚠ 默认在**所有群**启用，意味着心流接话是**公开可见**的；误判会当众发出。频率总闸与
> 保守触发是为了把打扰压到最低；不想要就把 `group_flow_enabled` / `group_icebreak_enabled` 关掉。

## 关于 Humanoid Core（可选依赖）

装了「Humanoid Core」插件时，插件会读它的状态并把它当**参考值**用：

| Core 给的 | 插件怎么用 |
|---|---|
| `body` 精力/社交能量/睡意/饥饿/困意 | 念头增速的油门与刹车；低于阈值时念头几乎涨不动 |
| `body.asleep` | 硬否决：日程写着她在睡就不发 |
| `routine` 生物钟夜 | **安静时段按这个判**，而不是插件配置里写死的 23 点（夜猫子人格凌晨四点睡，用 23 点判是错的） |
| `form.burst_ok` | 这一轮适不适合连着发 |
| `form.question_bias` | 偏低时提示「你这一轮不太想问句」 |
| `form.long_reply_ok` | 为 false 时把长度上限收到 40 字 |
| `form.max_chars` | 这一轮的单条字数上限 |
| `activity` / `day` / `weather` | 素材：她今天在干什么、在哪、外面天气 |
| `feelings` | 身体感觉，出现在提示词里但要求「不要在消息里报告它们」 |

反过来，插件把「刚替谁主动开过口、被连着冷落几次」写回 Core 的 `humanoid_signals.json`，
Core 据此泄掉社交欲望、生成一句压着的挂念。两边各写各的文件，不存在并发写。

Core 的 `humanoid/wording.py` 里写着一句话，本插件现在也是这么做的：
**「这里不写台词也不写规矩，只描述状态」**。

> `mode=standalone` 表示完全不读 Core。`mode=auto`（默认）是有就读、没有就降级。
> 曾经还有一个 `mode=humanoid`（号称「强制要求 Core」），但代码里从来没有对应实现，
> 选它和 auto 行为完全一样——一个假装存在的档位比没有更误导人，已经删掉。
>
> **降级是可见的**：`/自主社交状态` 会明确列出当前读到了哪一层、哪些能力因为
> 读不到 Core 而停用了。不会再出现「装了个 Core，插件却像没装一样」而查不出原因。

## 功能

### 核心机制
- 念头（urge）惰性积分：只在被读到时按经过的时间补算，不为每个人挂定时器。
- 冷却项是**护栏**（防刷屏），不是节奏的来源。
- 安静时段与对方作息是硬闸：那个点就是不发，念头留着等合适的时候。
- LLM 同时负责「要不要说」和「说什么」；调度、积累、结算全在插件里。
- 播种：历史导入（读回装插件前就聊过的人）与播种名单（没聊过的人也能被主动找上）。

### 决策不会自相矛盾
- 引擎的闸门已经放行之后，提示词**不会**再劝模型「别发」——这两处曾是各说各话，
  导致每次到点都白烧一次 LLM 换一个「不说」。
- 模型必须按 `SEND`/`NO` 协议作答。**没按协议作答时本轮不发**：这类回答写的往往是
  「我觉得现在不太合适」这类犹豫说明，当正文发出去就是机器人当众自曝思考过程。
- 单次 LLM 调用有 90 秒超时，失败连续 3 次起指数退避并把原因写进日志。调用挂住
  不会把后台循环卡死。
- **日志不会刷屏**：持续故障（key 失效、平台掉线、磁盘满）时，同类日志按 5 分钟窗口
  聚合，只记第一条，末尾补一句「期间另有 N 次同类，已省略」。故障恢复后计数清零，
  下次再坏能立刻报出来。

### 拟人化特性

**时段与作息**：7 个时段的语气指导，加上按每个人自己的活跃小时画像挑时机。周末念头涨得快一些。

**能量影响**：读取 Humanoid Core 的精力与社交能量。累了不是「概率打折后照发」，而是念头根本攒不起来。

**发送后的体验**：被接话会在意度上加分、冷落计数归零；没人理会降分、抬高下次门槛。回复率统计用 `reply_window_hours`，但「TA 是不是不想理我」的判定至少给半天 —— 晚上发的话对方早上才回，完全正常。

**不替她说话**：插件只提供**身体值**和**参考值**，不替 AI 写台词、不给它念稿子——
- **不给她现成的句子**。以前有 45 条固定例句（「刚想到一个事」「楼下的猫又在晒太阳」…）让她挑，
  结果每轮都在这几十句里轮着挑，看着像人，其实在背稿子。现在一条都没有。
- **不替她编经历**。以前有 80 条「她现在可能在想什么」（“楼下卖早餐的香味飘上来了”），
  相当于掷骰子决定她今天吃了什么、心情如何。现在动机由模型自己在生成前产生。
- **给素材，让她自己决定说什么**：现在几点、距上次跟 TA 说话多久、TA 最后说了什么、
  挂着什么事、她今天在干什么、外面天气——并明确告诉她「别编这里没有的事」。
- **给风格画像，不给句子**：从真实对话历史统计「TA 一条平均 7 个字、最长 11 字、
  基本不问句、习惯用句号收尾」。约束的是长度和结构，内容由模型造。

**对话记忆**：每人最近若干条对话（**包括她自己在主链路里说的话**）、话题关键词、时间锚点（「明天面试」）、没说结果的挂事（「今天面试了」）。prompt 里会单列「你自己上一句对TA说的是」。

**关系分级**：5 个关系档位决定能说什么、示例给到哪一档。

**消息类型**：6 种（分享想法、表达感受、延续话题、随口招呼、自然关心、时间反应）。

**反重复**：最近几次消息类型降权，并把最近发给对方的几条列进 prompt 要求换句式。

**连发模式**：主动消息可自然拆成 2-3 条短句，隔 1-3 分钟逐条补发；期间对方回话即停。上限由 `max_burst_parts` 控制。

**用人格设定说话（按角色隔离，插件里没有人格配置项）**：主动消息直接取 AstrBot 内置人设，按目标会话解析。解析链与正常聊天一致，所以**多角色天然各用各的**。读不到人设时回退默认口吻，不阻塞发送。

**输出清洗**：markdown 符号、「消息：」标签前缀、泄进来的 `SEND` 协议标记、中文弯引号包裹、超长在句子边界截断；还会按开关去掉**括号动作与旁白**（`（轻轻为你披上薄毯）`、`*摸摸头*`）和 emoji。

### 权限
`/触发社交` 与 `/自主社交状态` 默认**仅机器人主人**（AstrBot 全局配置 `admins_id`）可用。非主人在群里触发这些指令时插件**完全静默**——拒绝回复本身就会告诉所有群成员「这里有个能用的指令」。需要放开给别人，把 `owner_only_commands` 关掉并填 `allowed_trigger_uids`。`/自主社交状态` 的输出末尾会附上权限判定依据（你的 ID、主人列表、白名单），填错了照着这一行就能看出来。

### 性能
- Core 状态每个周期只读一次磁盘（按文件指纹缓存）。
- 观察消息标脏 + 周期刷盘；状态写入原子（tmp + replace）。
- 长期不活跃用户的历史正文、话题与作息画像自动清理（`user_retention_days`）。
- **状态文件读不出来时不会覆盖它**：先备份、再报错、并暂停写盘，等你修好文件重载插件。

### 兼容性
- 支持 `auto`、`standalone` 两种模式；与 Humanoid Core 只读衔接，不修改 Core 状态。
- 优先读 Core v2.14+ 的 `contract` 快照，读不到就按旧字段走。
- 主动消息依赖 `context.send_message`。qq_official 这类不支持主动发送的平台会发送失败，
  此时**不会**误记冷却与统计，也不会把用户隔离——那是平台的能力问题，不是这个人的问题。
- 社交状态按 bot 独立保存；状态文件自动补齐新字段。
- 兼容 AstrBot v4 新旧两套 API；引擎与状态层共用同一个可注入时间源。

## 配置项怎么理解

**67 个配置项，但真正需要动的通常只有 4 个**：

| 想达到的效果 | 调这个 |
|---|---|
| 整体更/更少主动说话 | `activity_level`（默认 75） |
| 两条消息之间至少隔多久 | `urge_refill_hours`（默认 2 小时） |
| 刚聊完多久内不另起话 | `recent_talk_minutes`（默认 18 分钟） |
| 晚上几点到几点不说话 | `quiet_start` / `quiet_end`（默认 23–7） |

其余项基本都有合理默认值，动之前先读下面的说明。

> **一个必须知道的精度问题**：插件是按「心跳」醒来的，默认每 8–15 分钟看一眼。
> 所以 `probe_after_minutes`（默认 2 分钟）这类分钟级配置，**实际最快也要等一个心跳**
> 才可能触发——把它从 2 调到 3，在默认心跳下不会有任何区别。想让分钟级配置真正按
> 分钟生效，把 `heartbeat_min_minutes` 调到 1。心跳变快**不会**让你多发消息
> （发不发仍由念头与冷却决定），只是让「到点了」被发现的时机更准。

> **升级后节奏没变**：AstrBot 不会覆盖你已有的配置。插件**不会**偷偷改你的设置——
> 启动时只在日志里告诉你哪些项还停在旧版本的默认值上，要不要跟新版节奏由你在面板里决定。

## 全部配置项

> 下表与 `_conf_schema.json` 同源，面板里看到的默认值与这里一致。

| 配置 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `mode` | `auto` | `auto` 自动探测 Core；`standalone` 完全不读 Core |
| `activity_level` | `75` | 整体想说说话的程度，缩放念头积累速度（不是「每隔几分钟发一条」）；不影响未完话题那几条 |
| `urge_refill_hours` | `2` | 【节奏】最在意的人攒满一次念头大约要多少小时；一般熟的人按比例更慢。只管另起话题 |
| `recent_talk_minutes` | `18` | 【节奏】刚聊完多久之内绝不另起新话题（不影响未完话题那几条） |
| `heartbeat_min_minutes` | `8` | 心跳间隔下限（分钟）。**决定所有分钟级配置的实际精度** |
| `heartbeat_max_minutes` | `15` | 心跳间隔上限（分钟），实际间隔在上下界之间随机取 |
| `llm_gate` | `true` | 发送前让模型判断该不该说，它可以说 NO |
| `skip_cooldown_minutes` | `10` | 模型否决后，多久之内不再就同一个人重新纠结 |
| `respect_user_rhythm` | `false` | 按对方平时的活跃时段挑时机。**默认关**：本插件就是用来主动社交的，不该拿「对方现在多半没在线」压住开口的时机；深夜由 `quiet_start`/`quiet_end` 单独兜底 |
| `cue_followup` | `true` | 记住对方说的时间锚点，到点当成开口的由头 |
| `followup_enabled` | `true` | 【未完话题】这场话断了就接一句（自动分「追问那件事」与「问在不在」两种） |
| `probe_after_minutes` | `2` | 【未完话题】对方回得敷衍时，隔多久追问那件事 |
| `followup_after_minutes` | `4` | 【未完话题】双方都不说话了，隔多久问一句在不在 |
| `followup_max_minutes` | `70` | 【未完话题】超过这么久就别接了，像隔半天重新打招呼 |
| `followup_cooldown_minutes` | `30` | 【未完话题】两次接话之间的最短间隔（同一段沉默只会接一次，这是跨段护栏） |
| `loop_enabled` | `true` | 【回访】记住对方提过、没说结果的事，过几小时问后来 |
| `loop_min_hours` | `2.5` | 【回访】回访窗口的下沿 |
| `loop_max_hours` | `14.0` | 【回访】回访窗口的上沿 |
| `closer_enabled` | `true` | 【收场】她主动发的话一直没人接时，自己冒一句收场 |
| `closer_after_hours` | `8` | 【收场】隔多久没人回才适合自己收尾（一共最多收三次） |
| `track_own_replies` | `true` | 【拟人地基】把 bot 自己说过的话也记进对话账本，追问才接得上话头 |
| `use_core_clock` | `true` | 【时区】安静时段与作息画像按她所在城市的小时算（需 Core 提供时区） |
| `user_cooldown_minutes` | `30` | 【护栏】同一个人两次被主动联系的最短间隔（每人独立，互不排队） |
| `max_sends_per_round` | `3` | 【护栏】一轮心跳里一个角色最多主动联系几个不同的人（防刷屏总闸） |
| `quiet_start` | `23` | 安静时段开始（小时） |
| `quiet_end` | `7` | 安静时段结束（小时） |
| `private_only` | `true` | 仅私聊。关掉后请确认你清楚后果：群会话也可能被导入成「人」 |
| `debug` | `false` | 决策日志（谁攒满了念头、为什么没说） |

| `topic_memory_count` | `5` | 话题记忆数量 |
| `context_inject_count` | `10` | 生成时注入多少条最近对话当上下文（含 bot 自己的发言） |
| `weekend_boost` | `true` | 周末念头涨得快些 |
| `energy_threshold` | `15` | 精力低于此值念头几乎涨不动（需 Core） |
| `social_energy_threshold` | `20` | 社交能量低于此值念头涨得极慢（需 Core） |
| `adaptive_reply_rate` | `true` | 把「对方接不接话」算进在意度 |

| `allowed_trigger_uids` | `[]` | 额外白名单，仅在 `owner_only_commands` 关闭时生效 |

## 升级（覆盖安装）
AstrBot 的「本地安装 zip」不会覆盖同名目录：装过旧版时直接上传会报
`安装失败：目录 astrbot_plugin_autonomous_social 已存在。`，插件列表里的「更新」也只会报
`该插件不是通过插件市场安装，无法检测或执行更新。`（上传安装的插件没有市场来源）。
所以升级二选一，两种都不丢状态与配置：

1. 面板：插件 → 本插件 → 卸载（**不要勾**「删除配置」「删除数据」）→ 立即上传新 zip。
   配置在 `data/config/<目录名>_config.json`、状态在 `data/plugin_data/<目录名>/`，
   卸载只删 `data/plugins/<目录名>` 这一个目录，两个都不动。
2. 终端原地替换：先把新 zip 用「本地安装」上传一次（会失败，但包已落到
   `data/temp/plugin_upload_<原文件名>`），再解压覆盖 `data/plugins/<目录名>`，最后在面板点「重载」。

上传失败后如果 `data/plugins/` 里留下 `plugin_upload_*` 之类的残留目录，或插件出现在
「加载失败的插件」列表里，要先把它删掉/卸载，否则下次上传仍会撞「目录已存在」。

  不会拿空状态盖掉它。修好文件后重载插件即可恢复。

## 指令
- `/自主社交状态`：念头面板（谁攒到多少、多久没说话、上次是被接住还是没接）、当前节奏参数、Core 与人格联动、**当前读到了哪一层、哪些能力因读不到 Core 而停用**、LLM 退避状态、权限判定依据。仅主人/白名单。
- `/触发社交`：立刻挑念头最重的人说一句，绕过念头门槛与冷却，也不经过模型否决（主人要看效果就别替他否决），但仍不插话进热聊。
  触发前会先验三件事——引擎在跑吗、插件启用了吗、模型是不是正在失败退避中——任何一条不满足都直接拒绝并说明原因，不动任何状态。
  万一第一个候选人发不出去（模型抖一下、平台断一下），会自动换下一个，最多试 3 个；全失败时汇总每一位的原因。仅主人/白名单。
- `/主动消息记录 [用户ID]`：看最近 7 天发过的主动消息（按用户隔离不串台）。仅主人。
- `/群社交状态`：群聊心流在管的群列表——最近活跃、心流窗口是否开着、是否被隔离（被踢/会话失效）。仅主人。
