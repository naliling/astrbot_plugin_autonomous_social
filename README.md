# 自主拟人社交

标准 AstrBot 插件结构，版本 1.8.0。

## 它解决什么问题

让 bot 在**没有收到消息的时候**也主动找熟人说话，而且说得像个有自己生活的人，不像一个定时器。

主动开口其实是几件不同的事，本插件把它们走成几条互不依赖的路：

| | 什么时候开口 | 靠什么 |
|---|---|---|
| **另起一个新话题** | 慢慢来：得真的想说（urge 攒满） | `urge_refill_hours`、`activity_level`、作息画像 |
| **追问那件事** | 几分钟：对方回得越来越敷衍 | `probe_after_minutes`（不看 urge） |
| **问一句在不在** | 十几分钟：话说到一半人没了 | `followup_after_minutes`（不看 urge） |
| **回访没结果的事** | 几小时到一夜：你提过一句没说后来 | `loop_min_hours` / `loop_max_hours` |
| **给悬着的话收场** | 几小时到几天：她主动发的没人接 | `closer_after_hours`（最多收三次） |

## v1.8.1：修一个把插件堵死的括号

那个注册函数只收关键字参数，于是所有人安装/更新都失败，报的是
`TypeError: register_after_message_sent() takes 0 positional arguments but 1 was given`。
1.8.1 就是把它补上，功能与 1.8.0 逐字相同。

已经被 1.8.0 堵住的：那个坏版本已经插件市场发出去了，所以光点「更新」不够——先确认
`data/plugins/astrbot_plugin_autonomous_social` 里已是 1.8.1 的代码（或先把它删干净再装），
她的配置与状态在 `data/config/` 和 `data/plugin_data/` 下，不会掉。

## v1.8.0：未完话题 + 让她看得见自己说的话

用户反馈很直接：「聊完之后我随便发几句，她不会回来追问」。查下来不是参数调得不对，是缺了
一块地基——**插件只看得见对方说的话**。bot 在主链路里回的每一句，它都不知道。

后果有三层：① 「最后一句是谁说的」永远判成对方的，那条「她说完对方没回就别追人」的保护
形同虚设；② 反过来，「她上一句问了什么」完全不知道，于是最该发生的追问根本没有依据；
③ prompt 里的「最近的对话」全是对方单方面，她写出来的话接不上自己刚才说了什么，像换了个人。

**地基**：新增 `after_message_sent` 钩子（`track_own_replies`，默认开），把她说过的话记进
对话账本，并留下 `last_spoken` / `last_spoken_text` / `last_spoken_question`。命令回显
（`is_model_result()` 为假）不记；插件自己主动发的那句走 `record_outgoing`，不经过 respond
阶段，所以不会重复入账。已知缺口：流式回复分段送达时框架不触发这个钩子，那部分记不到。

**未完话题拆成三条路**（`social/threads.py`），全部不看 urge：

| 路 | 成立条件 | 说的是 |
|---|---|---|
| `probe` | 对方最近那句几乎没带信息（「还行」「就那样」「不知道」），沉默满 3 分钟 | 就着**那件事**追问，2~12 字 |
| `presence` | 刚才确实在来回聊，双方都不说话了，满 6 分钟 | 「刚才是不是卡了」这类接话 |
| `loop` | 对方提过一件没说结果的事（面试、复查、搬家），隔 2.5~14 小时到点 | 「对了你面试后来咋样」 |
| `closer` | 她主动发的话 8 小时没人接 | 「没事 就随口一说」，不要求对方回 |

几个反直觉但必须做对的地方（都是仿真里抓出来的）：

- **断点从「最后一个人说话」算起，不要求那句是对方说的**。旧版要求「最后一句必须是对方的」，
  而主链路一回复，最后一条永远是她的——这条路径于是永远不成立。那正是「不回来追问」的成因。
- **但对方那句必须还热着**（`now - last_seen <= followup_max_minutes`）。只看两人的最后发言会
  出另一个 bug：她在群里或跟别人说过话就重置了沉默计时，于是隔了半天还在追问人家早上那句。
- **「她上一句在问事」不算快速追问的理由**。她问了、对方没回，隔三分钟再追一次就是催；
  那个走 `presence` 的慢档。
- **收场最多三次**（`MAX_CLOSERS`）。收场那句本身会刷新 `last_sent`，没有这条上限的话，
  一个永远不接话的人会每天被收一次场，无限循环。实测：同一个人 3 天 6 条、7 天 6 条、
  14 天仍 6 条——试过就停了，这才是该有的样子。
- **`loop` 问完立刻清空**。挂着不删的话，每次心跳都会把它捡回来重问一遍。
- 四条路的字数区间、能不能用问句、要不要提出发点，在 `generator._MODE_NOTES` 里分开写。
  共用一段「问一句在不在」的文案，四条路就会长出一模一样的句子。

**默认更主动**：`urge_refill_hours` 4→3、`activity_level` 45→55、`global_cooldown_minutes`
30→20、`user_cooldown_minutes` 120→90、`followup_after_minutes` 12→6。AstrBot 更新配置只补缺
不覆盖，所以这些全部进了 `LEGACY_DEFAULTS`，老用户首次启动会一次性提升。

**修一个死配置**：`adaptive_reply_rate` 的说明写着「关掉后不再因被冷落而降速」，但全项目
除了解析没有任何地方读它。现在接到 `desire.interest_level(weigh_reply_rate=...)` 与念头天花板上。

**三天仿真实测**（一个会聊天的用户）：

| 配置 | 条数/天 | 构成 | 距对方最后一句 | 60 分钟窗口内最多 |
|---|---|---|---|---|
| v1.8.0 默认 | 3.3 | probe 50% / urge 30% / closer 10% / presence 10% | 中位 33 分钟 | 2 条 |
| 关掉三条路（≈v1.7.7） | 1.7 | urge 100% | 中位 426 分钟 | 1 条 |

## v1.7.7：断话跟进 + 按她的时区看表

「聊完十几分钟没回，是不是该问一句在不在」——旧版不会。那种事在旧版里也得等念头攒满：
12 小时仿真实测，10:00 聊完，下一条要到 **15:52** 才出来，而且内容已经变成另起一个话题。

现在走一条独立路径（`social/reasoning.py` 的 `dangling_reason`）：对方沉默落在
`followup_after_minutes`～`followup_max_minutes`（默认 12～90 分钟）之间就跟进一句。
以下四种情况**不跟**，为的就是不变成催：

- 最后一句是她自己说的（对方没回再去问「你怎么不理我」是追着人说）
- 之前没真聊起来（对方偶尔发一句就走了，不是「聊到一半」）
- 对方最后那句是「我去洗澡/开会/睡了」（新增的离开语词典，宁可不跟也不误伤）
- 她主动发的上一条还没被回（pending=waiting）

同一段沉默只跟一次（`followup_for` 记住是为哪一次沉默跟的）；发出去后照旧计入 pending，
所以对方一直不回也不会连环追问。写话时带 `intent=followup`：目标 4~14 字、这一句就是
问话（覆盖掉平时「多说陈述句少用问句」那条）。

**时段判断改用她所在城市的小时**。`quiet_start/quiet_end`、作息直方图、以及 prompt 里
写给模型的「现在是几点」，以前全用宿主机时钟（Core 契约里带了时间，桥接层读了但没人用）。
插件跑在北京时区、她设在加里宁格勒时，安静时段差 6 小时——她的白天被当成深夜。现在按契约
里的 `utc_offset_minutes` 换算（`use_core_clock`，默认开）；拿不到契约时退回本机时钟而不是
当成 UTC。**记账与判断用同一个小时**：分开的话作息画像与闸门差几个钟头，
`respect_user_rhythm` 会永远判成「这个点 TA 不玩手机」。

默认节奏也提了一档（`urge_refill_hours` 8→4、`recent_talk_minutes` 45→30），并且进了
`LEGACY_DEFAULTS`：AstrBot 更新配置只补缺不覆盖，不改这一条的话老用户升完级仍跑在 8/45。

实测（10:00 聊完然后对方消失，12 小时）：

| 配置 | 什么时候开口 | 说的是 |
|---|---|---|
| 念头 8h、无跟进（v1.7.6） | 15:52 | 另起一个话题 |
| 本版默认 | 10:12 | 跟进一句在吗 |
| 念头 24h + 跟进 | 10:12 | 跟进一句在吗 |

## v1.7.6：Token 预算

本插件只在一处调模型：准备主动开口前那一次「该不该说 + 说什么」（decide 与 generate 共用
同一段 prompt）。实测：生产最坏情况（人设 800 字 + 5 条历史 + 完整背景）**输入约 2100 token**，
输出受 `max_message_length` 限制，合计远不触顶。

仍然加了一道与调用方无关的硬预算（`PROMPT_TOKEN_BUDGET = 6000` token）：超了就按固定
优先级丢块——反例示例 → 正例示例 → 话题 → 最近说过什么 → 连发提示 → Core 背景 → 内心
描述 → 历史 → 人设截短。**不会从中间硬截整段 prompt**（截在句子中间会把输出格式要求切掉，
模型就开始自由发挥）。任务指令、关键要求、输出格式三段永不丢。丢时打一条 info 日志。

人设在 `persona.py` 里本来就截到 800 字，但生成器不该信任调用方，所以预算里还有一道
`PERSONA_SHED_CHARS = 400` 的保险层。实测有人把 AstrBot 人设写成 9000 字时：原本会发出
约 10500 token 的请求，现在自动降到约 1100。

## v1.7.5：接上身体

前一版的念头模型已经对了，但它能读到的身体只有两个标量：`energy` 与 `social_energy`。
所以会出现「凌晨四点精力 80，于是照样发一条一百多字的晚安」——它看不出她是不是真的在睡、
饿不饿、身上舒不舒服，也看不出她到底有没想说这句话。

Humanoid Core v2.14 开始把身体导出成一份带版本号的契约快照（`state.json` 里的
`roles[bid].self.contract`），这一版改成优先读它：

- **`social_desire` 成了油门和刹车**。她独处时这个量自己涨，聊过之后泄掉；本插件的念头
  增速直接乘上它。于是「刚聊完」与「一个人待了一整天」是两种完全不同的节奏，不再靠一个
  全局冷却值近似。
- **`asleep` 是硬否决**。日程写着她在睡，就不再发，而不是概率打折后照发。
- **困意、饥饿、不适**各自压低念头增速：困透了的人不会到处找人聊天。
- **`form.max_chars` 约束这一句写多长**。Core 说「这一轮只说一两句」，主动消息就真的只有
  一两句，不会顶到 `max_message_length` 写成小作文。
- **`feelings` 进 prompt**，让她带着身体的感觉说话（「眼皮很沉」），而不是报告数值。
- **写回信号**：`humanoid_signals.json`（自己目录下，Core 只读）。内容就三样——刚替谁
  主动开过口、被连着冷落几次、当前想说话的程度。Core 拿前两条去泄掉社交欲望、生成一句
  压着的挂念。两边各写各的文件，不存在并发写同一个 state.json。
- 拿不到契约（没装 Core、或 Core 还是 v2.13.x）时，全部退回读旧字段，行为与 v1.7.4 一致；
  `/自主社交状态` 会显示到底读到了哪一层。

## v1.7.4 的关键改动：从定时器改成念头

旧版是「每 2-9 分钟掷一次骰子，掷中了就挑个人发一条」。它的问题不在于概率算得不准，而在于这套流程里**根本没有「想不想」这个量**：骰子对所有人一视同仁，不管你们半小时前才聊完，也不管你上一条发出去对方压根没回。所以发出来的东西必然像闹钟 —— 凌晨四点给刚聊过两小时的人发一条「这一天辛苦啦，该休息了」，就是这套机制的标准产物。

现在每个人身上有一个随时间积累的 `urge`（想说话的念头）：

```
念头增速 = 在意程度 × 现在合不合适 × 我自己此刻的状态
```

- **越在意的人攒得越快**。在意程度由好感度、聊过的量、对方接不接话、被冷落几次合成，是个慢变量。
- **刚聊过直接清零**。真人才不会在话刚说完之后又另起一句无关的。
- **只在对方大概率醒着的时段攒得快**。插件按小时统计每个人平时的活跃时段，凌晨四点不是 TA 玩手机的时间，念头就攒得极慢；攒满了也会卡在闸门上等到合适的点。
- **对方不接话，就不再热脸贴冷屁股**。主动发出去超过半天没回，记一次「没接话」：在意度下调、念头天花板压低，连着三次之后没有具体由头就再也攒不出去。
- **攒满不等于就发**。先过规则闸门（刚聊过／上一条还挂着／说过要睡了／安静时段／作息不对），再由模型自己判断「现在这句到底该不该说」，它可以回答 NO —— 而这正是真人大部分时候的状态：想到了，然后觉得算了。
- **由头先行**。对方说过「明天上午面试」，插件记下这个锚点，到点之后把它当成主动开口的理由。真人大多是想起一件具体的事才说话的，没由头时更容易不发。
- **门槛每次重抽**。固定门槛会让间隔精确得像周期，所以每次说完话重新抽一个「这次要攒到多高才算想说」。

## 功能

### 核心机制
- 念头（urge）惰性积分：只在被读到时按经过的时间补算，不为每个人挂定时器。
- 全局冷却与用户冷却降级为**护栏**（防刷屏），不再是节奏的来源。
- 安静时段与对方作息是硬闸：那个点就是不发，念头留着等合适的时候。
- LLM 同时负责「要不要说」和「说什么」；调度、积累、结算全在插件里。

### 拟人化特性

**时段与作息**：7 个时段的语气指导，加上按每个人自己的活跃小时画像挑时机。周末念头涨得快一些。

**能量影响**：读取 Humanoid Core 的精力与社交能量。累了不是「概率打折后照发」，而是念头根本攒不起来。

**发送后的体验**：被接话会在意度上加分、冷落计数归零；没人理会降分、抬高下次门槛。回复率统计用 `reply_window_hours`（默认 2 小时），但「TA 是不是不想理我」的判定至少给半天 —— 晚上发的话对方早上才回，完全正常。

**对话记忆**：每人最近 10 条对话（**包括她自己在主链路里说的话**）、话题关键词、时间锚点
（「明天面试」）、没说结果的挂事（「今天面试了」）。v1.8.0 起 prompt 里会单列
「你自己上一句对TA说的是」，接话才接得上自己的话头。

**关系分级**：5 个关系档位决定能说什么、示例给到哪一档。没接 Core 时用在意程度估算档位，不至于永远按陌生人写。

**消息类型**：6 种（分享想法、表达感受、延续话题、随口招呼、自然关心、时间反应），平时只有约
10% 可能是问句；但未完话题那几条**就是要问一句**，各自的字数区间与要求分开写，不会被
「多说陈述句」那条压回陈述句。

**反重复**：最近 6 次消息类型降权，并把最近发给对方的几条列进 prompt 要求换句式。

**语气仲裁**：时段、精力、社交能量冲突时融合成自洽描述，不会出现「凌晨困倦」撞「精神不错」的矛盾指令。

**连发模式**：约 42% 的主动消息拆成两条短句，隔 1-3 分钟补发第二条；期间对方回话则取消，补发条不计入回复率与冷却。

**用人格设定说话（按角色隔离，插件里没有人格配置项）**：主动消息直接取 AstrBot 内置人设，按目标会话的 `unified_msg_origin` 解析。解析链与正常聊天一致：会话级指定 → 对话上的人设 → 该会话配置画像的默认人设 → 全局默认，所以**多角色天然各用各的**。插件里故意不放人格开关 —— 一个全局值会把所有角色压成同一个人格。读不到人设时回退默认口吻，不阻塞发送。

**输出清洗**：markdown 符号、「消息：」标签前缀、泄进来的 `SEND` 协议标记（关掉 `llm_gate`
时模型照样会带，少了这一道会真发出去一句「SEND对了你面试后来咋样」）、中文弯引号包裹、超长在句子边界截断、句尾「。」去掉；v1.7.4 起还会去掉**括号动作与旁白**（`（轻轻为你披上薄毯）`、`*摸摸头*`）和 emoji —— 语C 风人格最容易交回这种东西，而微信里没人这么打字。两个行为分别由 `strip_roleplay_actions`、`allow_emoji` 控制。

**Prompt 工程**：正反例引导语气、动机不照搬、每条抽一个具体目标字数（以短句为主）、禁爱称刷屏、禁催睡、禁「作为AI」自述，并把当前念头状态写成一段内心描述。

### 权限
`/触发社交` 与 `/自主社交状态` 默认**仅机器人主人**（AstrBot 全局配置 `admins_id`）可用。非主人在群里触发这两个指令时插件**完全静默**，不当众回应 —— 拒绝回复本身就会告诉所有群成员「这里有个能用的指令」。需要放开给别人，把 `owner_only_commands` 关掉并填 `allowed_trigger_uids`。`/自主社交状态` 的输出末尾会附上权限判定依据（你的 ID、主人列表、白名单），填错了照着这一行就能看出来。

### 性能
- Core 状态每个周期只读一次磁盘（按文件指纹缓存），候选用户共享。
- 观察消息标脏 + 周期刷盘；状态写入原子（tmp + replace）、紧凑序列化。
- 长期不活跃用户的历史正文、话题与作息画像自动清理（`user_retention_days`）。

### 兼容性
- 支持 `auto`、`humanoid`、`standalone` 三种模式；与 Humanoid Core 只读衔接，不修改 Core 状态。
- 优先读 Core v2.14+ 的 `contract` 快照（v2.15 起契约多了 `day` 与 `persona` 两段，读不到
  就按旧字段走）；两代 Core 都能用。
- 主动消息依赖 `context.send_message`。qq_official 这类不支持主动发送的平台会返回 `False`，此时按发送失败处理，不会误记冷却与统计。
- 社交状态按 bot 独立保存；状态文件自动补齐新字段（旧版 v1 结构会先迁移到 v2）。
- 兼容 AstrBot v4 新旧两套 API；引擎与状态层共用同一个可注入时间源。

## 升级（覆盖安装）
AstrBot 的「本地安装 zip」不会覆盖同名目录：装过旧版时直接上传会报
`安装失败：目录 astrbot_plugin_autonomous_social 已存在。`，插件列表里的「更新」也只会报
`该插件不是通过插件市场安装，无法检测或执行更新。`（上传安装的插件没有市场来源）。
所以升级二选一，两种都不丢状态与配置：

1. 面板：插件 → 本插件 → 卸载（**不要勾**「删除配置」「删除数据」）→ 立即上传新 zip。
   配置在 `data/config/<目录名>_config.json`、状态在 `data/plugin_data/<目录名>/`，
   卸载只删 `data/plugins/<目录名>` 这一个目录，两个都不动。
2. 终端原地替换：先把新 zip 用「本地安装」上传一次（会失败，但包已落到
   `data/temp/plugin_upload_<原文件名>`），再解压覆盖 `data/plugins/<目录名>`，最后在面板点「重载」。

上传失败后如果 `data/plugins/` 里留下 `plugin_upload_*` 之类的残留目录，或插件出现在
「加载失败的插件」列表里，要先把它删掉/卸载，否则下次上传仍会撞「目录已存在」。

## 数据
- `data/plugin_data/astrbot_plugin_autonomous_social/state.json`：本插件自己的状态。
- `data/plugin_data/astrbot_plugin_autonomous_social/humanoid_signals.json`：写回给
  Humanoid Core 的信号（Core 只读，超过 15 分钟不采信）。**v1.8.2 起引擎启动时就写第一份，
  之后每轮刷一次心跳**——以前三个 setter 都在「值没变」时提前 return，冷落计数为 0、
  欲望拿不到时这个文件永远不会出现，Core 那边就显示「读不到信号」，跟真没装一样。
  装完两边都重启一次，Core 的 `/拟人诊断` 会显示「社交层信号：读到并在用」。

## 指令
- `/自主社交状态`：念头面板（谁攒到多少、多久没说话、上次是被接住还是没接）、当前节奏参数、Core 与人格联动、权限判定依据。仅主人/白名单。
- `/触发社交`：立刻挑念头最重的人说一句，绕过念头门槛与冷却，也不经过模型否决（主人要看效果就别替他否决），但仍不插话进热聊。仅主人/白名单。

## 配置项

| 配置 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 是否启用自主社交 |
| `mode` | `auto` | `auto`／`humanoid`／`standalone` |
| `activity_level` | `55` | 整体想说说话的程度，缩放念头积累速度（不是「每隔几分钟发一条」）；不影响未完话题那几条 |
| `urge_refill_hours` | `3` | 【节奏】最在意的人攒满一次念头大约要多少小时；一般熟的人按比例自动更慢。只管另起话题 |
| `recent_talk_minutes` | `25` | 【节奏】刚聊完多久之内绝不另起话题（不影响未完话题那几条） |
| `followup_enabled` | `true` | 【未完话题】这场话断了就接一句（自动分「追问那件事」与「问在不在」两种） |
| `probe_after_minutes` | `3` | 【未完话题】对方回得敷衍时，隔多久追问那件事 |
| `followup_after_minutes` | `6` | 【未完话题】双方都不说话了，隔多久问一句在不在 |
| `followup_max_minutes` | `90` | 【未完话题】超过这么久就别接了，像隔半天重新打招呼 |
| `followup_cooldown_minutes` | `45` | 【未完话题】两次接话之间的最短间隔（同一段沉默只会接一次，这是跨段护栏） |
| `loop_enabled` | `true` | 【回访】记住对方提过、没说结果的事，过几小时问后来 |
| `loop_min_hours` / `loop_max_hours` | `2.5` / `14` | 【回访】回访窗口的上下沿 |
| `closer_enabled` | `true` | 【收场】她主动发的话一直没人接时，自己冒一句收场，而不是从此静音 |
| `closer_after_hours` | `8` | 【收场】隔多久没人回才适合自己收尾（一共最多收三次） |
| `track_own_replies` | `true` | 【拟人地基】把 bot 自己说过的话也记进对话账本，追问才接得上话头 |
| `use_core_clock` | `true` | 【时区】安静时段与作息画像按她所在城市的小时算（需 Core v2.14.2+） |
| `llm_gate` | `true` | 发送前让模型判断该不该说，它可以说 NO |
| `skip_cooldown_minutes` | `40` | 模型否决后，多久之内不再就同一个人重新纠结 |
| `respect_user_rhythm` | `true` | 按对方平时的活跃时段挑时机 |
| `cue_followup` | `true` | 记住对方说的时间锚点，到点当成开口的由头 |
| `global_cooldown_minutes` | `30` | 【护栏】两次主动消息的最短间隔 |
| `user_cooldown_minutes` | `120` | 【护栏】同一个人两次被主动联系的最短间隔 |
| `quiet_start` / `quiet_end` | `23` / `7` | 安静时段：这段时间念头几乎不增长，且到点也不发（开了 `use_core_clock` 就按她那里的小时） |
| `private_only` | `true` | 仅私聊 |
| `debug` | `false` | 决策日志（谁攒满了念头、为什么没说） |
| `max_message_length` | `60` | 单条最大长度（字） |
| `strip_roleplay_actions` | `true` | 去掉括号动作与旁白 |
| `allow_emoji` | `false` | 是否保留 emoji |
| `allow_burst` | `true` | 连发模式 |
| `topic_memory_count` | `5` | 话题记忆数量 |
| `weekend_boost` | `true` | 周末念头涨得快些 |
| `energy_threshold` | `15` | 精力低于此值念头几乎涨不动 |
| `social_energy_threshold` | `20` | 社交能量低于此值念头涨得极慢 |
| `adaptive_reply_rate` | `true` | 把「对方接不接话」算进在意度 |
| `reply_window_hours` | `2` | 多久内回话算「接住了」（回复率统计口径） |
| `owner_only_commands` | `true` | 两个指令是否仅主人可用 |
| `allowed_trigger_uids` | `[]` | 额外白名单，仅在 `owner_only_commands` 关闭时生效 |
| `store_message_text` | `true` | 是否把私聊正文存入 state.json |
| `user_retention_days` | `30` | 长期不活跃用户的历史正文清理天数，0 = 永不清理 |
