> **她攒够了念头，会先开口。**
> 没说完的话，她记得回来问。
> 不是定时器：什么时候开口、对谁开口、说什么，由念头和一件具体的事决定。

## 一分钟上手

1. 装好插件，在面板里把 **总开关**（`enabled`）打开。
2. 确认 **主动消息时区**（`timezone_offset`）：填你和她在用的那个钟（默认 `UTC+8`）。填错的表现是「她整个上午都不在」。
3. 想指定模型就填 **主动消息专用模型**（`proactive_provider_ids`）；留空表示跟着当前会话的模型走。
4. 私聊与群聊是两把独立的锁：**允许私聊**（`allow_private_chat`）、**允许群聊**（`allow_group_chat`）。只想要私聊就把群聊关掉。
5. 改完配置记得重载插件；面板里的子项只有在父开关打开后才出现。

## 注意事项（照着对一遍）

- **人格写得粗，发出来的话就粗。** 这个插件只负责「什么时候开口、不把同一件事说第二遍」；说得像不像那个人，取决于人设（AstrBot 人格设定或 Core 的角色设定）写得多具体——她是谁、什么语气、身体是什么形态、每天在做什么、跟这个人熟到什么程度。人设只写两行，换什么模型都只能得到两句空话：**不是有模型就行。**
- **安静时段按时区算，不按服务器时间。** 放这里调：**主动消息时区**（`timezone_offset`）定钟；**安静时段按谁的钟**（`quiet_clock`）选 `local`（本机）或 `core`（她所在城市）。面板上填的 23 到 7 是那个钟的 23 到 7。
- **她一句话都不说，先看三条：** 是否正处安静时段；**精力低于此值不开口**（`gate_energy_floor`）与 **社交能量阈值**（`social_energy_threshold`）是否把她拦在门外；日志里有没有 `LLM 调用超时` 或 `LLM 不可用（…）`。
- **严格模式会让它宁可不发。** **专供模型取不到就坚持不发**（`strict_proactive_provider`）打开时，专供模型全挂就真的不发；想退回会话默认模型，把它关掉。
- **分段连发由 AstrBot 的「分段回复」决定**，本插件只负责间隔（最低 1.2 秒）。那边把间隔填成 0.5 秒，看起来就是机关枪。
- **普通回复的出口清理只对非流式回复生效。** WebUI 的流式回复由框架直接下发，插件拿不到发送前那一步。
- **长期记忆要另装插件。** 面板里的「消息记录」是本插件的本地留存；真正的跨会话长期记忆需要 `astrbot_plugin_memory_companion`，没装时 **联动长期记忆插件**（`memory_bridge_enabled`）不起作用。
- **指令默认只有主人和 AstrBot 管理员能用**，要放开就填 **指令白名单**（`allowed_trigger_uids`）。
- **群聊主动发言有每日总量和每群额度**，额度用完后她只回话、不再主动开口。

## 常见问题

**她说的话越来越像复读？**
同一个群看 **同群别把同一件事说两遍**（`group_event_dedup_hours`），跨群看 **跨群别把同一件事说两遍**（`group_topic_dedup_hours`），群与私聊之间还有 **群和私聊别重复同一件事**（`cross_channel_dedup_hours`）。窗口内重复的说法会被拦住；嫌太严就把窗口调小。

**她为什么总在群里自言自语？**
群里本来没人说话时，她只能说自己。**群聊主动接话**（`group_flow_enabled`）负责接话（需要群里真有人聊），**群聊冷场破冰**（`group_icebreak_enabled`）与 **群内主动起话头**（`group_topic_enabled`）才是她主动开口的那两种。

**她说的事和日程对不上？**
Core 只保存当前状态、不保存历史日程，事后无法核对。v2.2.38 起群消息会把她用的那条素材一起落账（`samples[].sources`），要查就从那里查。

**配置项找不到了？**
子项挂在父开关下面：父开关关着时它在面板里是隐藏的（由 `condition` 控制），不是被删了。

**为什么她说「我也爱你」却没有上下文？**
主动消息不该用「也」——对方没说过的话不能接。这类句子会被改写或拒发。

**她叫错我的名字 / 干脆编一个名字？**
称呼按「Core 认定的称呼 → Core 文件里的称呼 → 本插件记的名片名」取，取到的是纯数字 UID 或一个字的残留值时会被跳过，继续往下找。如果她开始自己编名字，多半是三层都是空或都是无效值——去 Core 的角色设定里给她一个真名或昵称。

## 消息记录与长期记忆

- **消息记录（本插件自带）**：**主动消息也写进会话记录**（`persist_proactive_history`）、**保存私聊正文**（`store_message_text`）、**保存群聊正文**（`group_store_message_text`）决定要不要留原文；**记录保留多少天**（`user_retention_days`）与 **彻底删除闲置会话**（`purge_inactive_user_days`）决定留多久。
- **长期记忆（需要另装）**：**联动长期记忆插件**（`memory_bridge_enabled`）桥接 `astrbot_plugin_memory_companion`——生成前读这个人的长期记忆摘要，发完再写回去，只在私聊生效。没装这个插件时所有相关调用都返回空，行为与关闭一致。

## 它做什么

「自主拟人伴侣」让她在**没有收到消息的时候**也会主动找你，而且说得像个有自己生活的人，不像一个定时器。

- **先有件具体的事，才开口**：她刚做完的、你提过没下文的、到点该问的；
- **念头只管等多久，不管发不发**：攒够了也要有由头，派不出就不说；
- **不合适就憋着**：模型可以先否决，验收不过也会拦下；
- **三条不发**：派不出由头、模型否决、验收不过——都不发，念头留着下一轮再试。

一次主动消息大概这么走完：看状态 → 选人 → 找由头 → 过闸（安静时段、冷却、频率、关系档）→ 问模型该不该说 → 写 → 发 → 记账。

### 什么时候开口

- **主动开口** —— 攒够念头才开口；
- **未完话题** —— 没说完的会接上；
- **追问** —— 你敷衍时问那件事；
- **回访** —— 没结果的事回头问；
- **主动收场** —— 没人接就收尾；
- **问候** —— 隔久了问候一句；
- **静音结束** —— 到点先醒一次，不等下一轮心跳。

### 关系与分寸

- **关系分档** —— 越熟联系越自然，越生越克制；连着发不出去就停发，等对方先开口；
- **特别关心** —— 名单里的人放宽档位间隔、安静时段与「没回就停」；关系够近也能自动认定；
- **安静时段** —— 深夜不打扰；到点整轮不发（不是逐条拦），念头照常攒但攒得极慢；
- **同平台 bot** —— 也能聊；主动找它隔 6 小时、一天最多一条；
- **跨用户去重** —— 不群发同一句；
- **亲密联动** —— 和 Core 的亲密状态联动：关系足够近、她也确实想要时，会主动问一句（默认克制，受条件与冷却限制；更进一步的场景由 Core 侧默认关闭的进阶开关决定）。

### 群聊

- **群聊心流** —— 群里自然接话；群里刚安静下来不硬接；
- **破冰** —— 冷场时开个话头；
- **不点名** —— 主动开口不叫人；
- **群聊另算一套** —— 被叫到、接得上才接话；冷场时破冰；没话说就不发，不硬凑。

### 记得住

- **历史导入** —— 认识装插件前就聊过的人；
- **播种名单** —— 指定的人也能找；
- **关系记忆** —— 记得和每个人处到哪一步（好感、称呼、亲密史），不要求先聊过；
- **长期记忆** —— 按由头读记忆。

### 说话的样子

- **正在输入** —— 写的时候显示输入中；
- **连发** —— 拆成几条短句发；
- **说话习惯画像** —— 从真实聊天里统计她平时爱用的说法、emoji 和句长，生成时参考，不是套模板；
- **不反复说** —— 同一件事/同一句话不会反复发，理由会换着来；发出去前还有一道验收检查。

## 怎么用（三十秒）

**1. 装上**

AstrBot 插件页 → 本地安装，上传 zip；或者把整个文件夹放进 `AstrBot/data/plugins/`，然后重载插件。

**2. 面板里改配置**

不用手改文件。第一次只动四项就够：**活跃度**（`activity_level`，整体更主动 / 更安静）、**攒够一次主动要几小时**（`urge_refill_hours`，念头攒得多快：越小越主动）、**刚聊完的静默期**（`recent_talk_minutes`，刚聊完多久内不另起话）、**安静时段开始**（`quiet_start`） / **安静时段结束**（`quiet_end`，晚上几点到几点不说话）。其余项默认值已经调好。

**3. 看一眼通没通**

重载后发 `/自主社交状态`：权限判定依据、LLM 状态、Core 联动会一次列清。

> **升级注意**：用「本地安装 zip」时 AstrBot 不会覆盖同名目录——先卸载旧版（**不要勾**「删除配置」「删除数据」）再上传新 zip；如果是手动把文件夹放进 data/plugins/，可以直接覆盖后重载。两种方式状态与配置都不会丢。

## 指令

全部指令默认只有机器人主人（AstrBot 的 `admins_id`）与 AstrBot 管理员能用。要放给别人：先关掉 **指令只给主人用**（`owner_only_commands`），再把对方 ID 填进 **指令白名单**（`allowed_trigger_uids`，关闭后白名单才生效）；非主人在群里发这些指令时，插件完全静默。

| 指令（仅管理员） | 作用 |
| --- | --- |
| `/自主社交状态` | 看运行状态、念头面板、Core 联动、发送通道 |
| `/社交自检` | 不调模型不发消息，几毫秒查链路通不通 |
| `/触发社交` | 立刻挑一个最想说的人开口 |
| `/主动消息预览 [用户ID]` | 只生成不发送，看她此刻想说什么 |
| `/主动消息记录 [用户ID]` | 最近 7 天发过什么，附一句为什么 |
| `/群社交状态` | 群聊心流在管哪些群、是否被隔离 |

> 忘了哪条能看什么：先发 `/自主社交状态`，它会把权限判定依据、LLM 状态、Core 联动一次列清。

> **安静时段对手动触发一样有效。** `/触发社交` 走的是和心跳完全相同的那几道闸，所以落在安静时段里会被直接拦下，回执里写清原因和临时办法：「安静时段（23:00–07:00，本机 04 点），不打扰——手动触发和心跳走的是同一道闸。想现在看效果：把 **安静时段开始**（`quiet_start`） 与 **安静时段结束**（`quiet_end`） 填成同一个值即可关闭安静时段，或用 `/主动消息预览`（只生成不发送，任何时候都能用）。」——不会因为是你手点的就把人凌晨叫醒。这是 v2.0.6 起的行为：v2.0.5 只在「挑人」那一刻查一次，挑完到真正发出之间隔着的排队、生成、分段补发都能跨进深夜，手动触发更是直接发了出去。
>
> **夜里想测效果，两条路**：① 把 **安静时段开始**（`quiet_start`） 和 **安静时段结束**（`quiet_end`） 填成**同一个值**（比如都填 `23`）＝关闭安静时段，之后手动触发与心跳都会正常发；② 用 `/主动消息预览`，只生成不发送，任何时候都能看，不受安静时段影响。

## 配置

### 关键配置项

其余项大多有合理默认值，第一次用先看这四个：

| 想达到的效果 | 调这个 |
| --- | --- |
| 整体更主动 / 更安静 | **活跃度**（`activity_level`，默认 75） |
| 念头攒得多快（越小越主动） | **攒够一次主动要几小时**（`urge_refill_hours`，默认 1.5） |
| 刚聊完多久内不另起话 | **刚聊完的静默期**（`recent_talk_minutes`，默认 3 分钟） |
| 晚上几点到几点不说话 | **安静时段开始**（`quiet_start`） / **安静时段结束**（`quiet_end`，默认 23–7；两者填成同一个值＝关闭，夜里想测效果就用这招） |
| 让某些人一定收得到 | **特别关心名单**（`special_care_uids`，关系够近也能自动认定） |

> 想让她用会思考的模型说话：**主动消息专用模型**（`proactive_provider_ids`） 填主动消息专用模型，按顺序试第一个能用的；默认（空列表）跟随当前会话的模型。显式配了专供却一个都取不到时，默认**回退会话模型**并打一条一次性 warning；只有打开 **专供模型取不到就坚持不发**（`strict_proactive_provider`） 才「本轮不主动开口、等下一轮」——弱模型写出来的话，比不发更糟。

> 插件是按心跳醒来的（默认 8–30 分钟一次；可配范围：下限 1–60、上限 1–120），所以分钟级配置最快也要等一个心跳才生效。想让分钟级配置真按分钟走，把 **心跳间隔下限**（`heartbeat_min_minutes`） 调到 1。

### 全部配置项

> 下表与 `_conf_schema.json` 同源，共 142 项；第一列是配置键（面板里的英文名），第三列开头的中文名就是面板上显示的标签。父开关关掉时，子项在面板里是折叠的（由 `condition` 控制），配置本身仍然存在。

| 配置键 | 默认值 | 中文名与说明 |
| --- | --- | --- |
| `enabled` | `true` | **总开关**：关掉后她不再主动说话；面板与指令仍可用。 |
| `mode` | `auto` | **运行模式**：auto 自己判断该不该开口；manual 只回话、不主动。 |
| `timezone_offset` | `UTC+8` | **主动消息时区**：按这个时区算安静时段、问候和每日额度；auto 跟随本机。 |
| `activity_level` | `75` | **活跃度**：越高越容易攒够念头开口。 |
| `debug` | `false` | **调试日志**：把每一步判断的原因写进日志，排错时用。 |
| `allow_private_chat` | `true` | **允许私聊**：关掉后私聊里不主动开口，回话不受影响。 |
| `allow_group_chat` | `true` | **允许群聊**：关掉后群里不主动开口，被点名回话不受影响。 |
| `private_only` | `false` | **只主动私聊**：开：只找私聊的人说话，不在群里主动开口。与「只主动群聊」互斥，两个都开等于都不主动。 |
| `group_only` | `false` | **只主动群聊**：开：只在群里主动说话，不主动找私聊的人。回话不受影响。 |
| `proactive_provider_ids` | `[]` | **主动消息专用模型（见 strict_proactive_provider）**：留空等于跟着当前会话；取不到时默认回退跟随会话。 |
| `strict_proactive_provider` | `false` | **专供模型取不到就坚持不发**：开：宁可这一轮不发；关：回退到会话默认模型。 |
| `planning_enabled` | `true` | **先规划再写**：先让模型判断要不要说、说什么，再单独写正文。 |

## 联动

### 和人形化伴侣一起用（可选）

建议搭配 **humanoid_core v3.0.0 及以上**（契约 v2）。

- 装了：能读到她累不累、今天在忙什么、她那边几点——精力低就少开口；也能读到她的日程、天气、节日、穿着和称呼，主动开口更有由头；
- 装的是 2.28.x：基础联动仍可用（契约 v2 字段兼容），但 Core 3.0.0 之前的门面在插件重载后可能失效、读接口还会顺手写状态——这些修复只在 Core 3.0.0+ 生效，建议升级；
- `use_core_facade=on` 是**验证模式**：只走同进程门面、不读 Core 的 `state.json`，所以那些只能从文件派生的由头、CCB 等能力在 on 下会按预期降级（不是 bug）；日常用默认的 `auto` 就好；
- 没装：插件用自己的互动记录、念头和冷却判断，功能不受影响；
- 分工：人形化伴侣管她的生活，本插件管她什么时候开口。

### 和长期记忆一起用（可选）

装了「我会牢牢记住你」（memory_companion）时：开口前按这次的由头读这个人的长期记忆，发完再写回；没装照常发，只是少这一份记忆。

- **记忆联动仅私聊生效**：群聊的主动消息不读记忆，这是对方插件的可见性规则决定的，不是本插件省事；
- **写入有成本**：每写一条会触发一次 embedding 请求（对方插件的能力），成本很小但非零；
- 对方没装、桥接开关关着、接口对不上时，状态页的【联动】会分别说明原因，不会静默失效。

## 数据与边界

- **状态文件**：`data/plugin_data/astrbot_plugin_autonomous_social/state.json`
- **存什么**：互动记录、话题关键词、时间锚点、念头与节奏、发送记录
- **正文存不存**：**保存私聊正文**（`store_message_text`，默认开），关掉只记结构不记原文
- **保留多久**：**记录保留多少天**（`user_retention_days`，默认 30 天，0 = 永不清理）
- **整条记录清理**：**彻底删除闲置会话**（`purge_inactive_user_days`，默认 0 = 关；开了会永久删除整条会话记录，不只是正文）
- **读不出来时**：先备份成 `state.json.unreadable.<时间戳>` 再报错，不会拿空状态盖掉
- **平台边界**：主动消息要平台支持主动发送（如 qq_official 这类可能发不出去）；发失败不算一次成功交流，也不会误记冷却

## 从 1.28.x 升级到 2.0.0

- **数据不用迁移**：`state.json` 的结构与路径都没变，配置、互动记录、话题、念头与发送记录会原样继续；升级前备份一下 `data/plugin_data/astrbot_plugin_autonomous_social/state.json` 更稳。
- **安装方式不变**：AstrBot 插件页 → 本地安装，上传新 zip；或覆盖插件目录后重载。卸载时**不要勾**「删除配置」「删除数据」，否则配置与状态会被一并清掉。
- **显示名变了**：面板里显示「自主拟人伴侣」，插件 ID 仍是 `astrbot_plugin_autonomous_social`，数据目录与 Core 的联动发现都不受影响。
- **最低版本变了**：从 2.0.0 起要求 AstrBot **4.24.2** 及以上。
- **默认模型行为变了**：不再自带作者的私有模型 ID，默认跟随当前会话的模型；想指定专用模型就填 **主动消息专用模型**（`proactive_provider_ids`）。
